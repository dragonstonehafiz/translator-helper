Translation request flow

File submission, background processing, result polling and downloads.

Current implementation · 4 October 2026

1. File submission

The Translate page gets its selected file and series from shared state, then calls ApiService.translateFile(). The service sends multipart form data to POST /translate/translate-file, including languages and batch size.

The route checks that nothing else is running and the LLM is ready. It copies the upload into an operating-system temporary file, optionally loads the selected series, and calls start_translate_file(). That function reads the subtitles into memory once and hands the workflow to the orchestrator, which accepts it and returns straight away. If anything is rejected first, the route deletes the temp file and returns an error.

The initial response has status processing and {workflow: "translate_file"}. It does not contain the finished subtitles.

2. Task execution

Prepare batchesAsk the LLM for semantic groups, then split any group larger than the batch size.
ContextSelect relevant library information if a series is available.
TranslateTranslate each batch, with split and per-line fallbacks.
Save and clean upSave under files/outputs/translated, then delete the temp upload.

The orchestrator creates a timestamped log folder for the run, and tasks write numbered JSON diagnostics into it. The saved file keeps the input's extension, so the subtitle library writes the same format.

Source: backend/orchestrator/workflows/translate_file.py and backend/orchestrator/translate_file/.

3. Result polling

Once the start request is accepted, StateService calls GET /task-results/translate_file every second. The response is one snapshot of that workflow's state record:

StateResponse
Not run since the server startedidle, with only the workflow ID.
Runningprocessing, with the active task, its progress, message and ETA.
Finishedcomplete, with the result: the saved file's name and folder.
Failederror, with the error message; the failed task and its last progress stay in the data.

Polling lives in StateService, so it continues if the user leaves the Translate page, and stops on complete, error or idle. AppComponent reads the same state to draw the global progress overlay; the overlay does not poll the backend itself.

Progress counts belong to the active stage. 1 of 1 during planning is not the same unit as 100 of 200 lines during translation. This is stage progress, not a weighted percentage for the entire chain.

Source: backend/routes/task_results.py and frontend/src/app/services/state.service.ts.

4. Completion and downloads

When the workflow completes, the Translate page refreshes the file list for translated; if the user is on another page, the list is refreshed when they return. Downloading is a separate request through ApiService.getFileBlob().

Other workflows have different results: line translation and clip transcription return text; library updates return proposals; review returns the corrected file's name and how many lines were corrected.

Error handling

JSON responses use {status, message, data}. Some route rejections return an error envelope with the normal HTTP response status; validation and unhandled exceptions also have HTTP error responses. Frontend code therefore needs to inspect both the envelope and transport failures.

A failure during the run happens after the start response. The orchestrator records it in the workflow's state record, the next poll reports it, and StateService shows the error dialog even if the user has left the page. State records live in memory and disappear when the backend restarts; the run's log folder remains.

Sources: backend/utils/api_response.py and frontend/src/app/services/api.service.ts.

Requests outside the orchestrator

Listing files, downloading files, loading series and editing library entries use direct request/response handlers. Model loading uses utility endpoints and a threadpool rather than the task orchestrator. The task polling protocol is specifically for transcription, translation, review and library-update work.
