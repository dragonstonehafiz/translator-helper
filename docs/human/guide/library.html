Series library

What the library stores for each series, how it is filled from subtitle files, and what translation takes from it.

Current implementation · 4 October 2026

Series are listed and created on the Library page. Each series page has tabs for its characters, its glossary and Update Library. Adding, editing or deleting an entry by hand saves immediately.

Building the library

Update Library reads a subtitle file and suggests new characters, terms and facts. Nothing is saved until you accept a suggestion.

The update needs the LLM and web search to be loaded. The subtitle file chosen here is the same one selected on the Translate page.

StepThe model receivesIt returns
1. Find names, terms, eventsThe whole transcript with speakers, and the names, aliases and terms already in the libraryEvery character name, series term and key event in the episode
2. Check against libraryThe findings and the library's names and termsWhich names and terms are already known; events are passed on unchanged
3. Write search queriesThe unknown names and termsOne web search per item. Skipped when nothing is unknown.
4. Search the webEach query, sent to Tavily rather than the modelUp to five text snippets per query. Skipped when there are no queries.
5. Propose additionsThe transcript again, the existing characters and glossary, what is known, and the search snippetsNew characters, new terms, facts to add to existing characters, and changes to existing terms
6. Remove repeated factsEach proposed character fact next to the facts already storedOnly the facts that are new

Accepting and rejecting

Each proposal is shown as a card. Accepting saves it through the same routes as editing by hand:

ProposalAccept
New characterAdds the character.
New glossary termAdds the term.
Character updateAdds the fact to the end of the field: personality, history, or the relationship with the named character.
Glossary updateReplaces the field with the proposed value.

Rejecting removes the card without saving anything. Proposals that haven't been accepted are lost when the browser is refreshed.

How repeated data is recognised

Repeats are caught in three places:

  1. Checking against the library. A name counts as known if it matches a library name or alias, allowing for other spellings, romanisations, honorifics and partial names. Known names and terms are never searched for or proposed as new.
  2. Proposing additions. The model sees every existing character and term and is told not to propose anything already recorded.
  3. Removing repeated facts. Each proposed character fact is checked again against what is stored. Personality and history facts are compared per character. Relationship facts are compared with every stored fact about the same named character. The model keeps only facts that are new in substance, even if worded differently.

The third check only covers facts for existing characters. New characters and glossary proposals are not checked again. If the check fails, the proposed facts are kept.

What translation uses

File translation and review use the library when a series is selected on the Translate page. Once per file, the model is shown the episode and the series' character names and glossary terms, and picks the ones that appear. Those entries are then sent in full with every translation request in the job.
