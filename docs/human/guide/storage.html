Files and storage

Everything the backend keeps on disk, and what each file looks like.

Current implementation · 4 October 2026

Folder map

There is no database. Everything the app writes goes under backend/files/, which is ignored by git. Each folder is created the first time something is written to it.

backend/model-files/ is the exception: you put .gguf files there yourself for the llama.cpp provider, and the app only reads it.

Model settings

Each provider's settings are saved to their own file in files/config/, named after the provider. The file is created with default values the first time the provider is used, and rewritten whenever its settings are applied on the Settings page.

API keys are stored here in plain text.

The fields in each file come from the provider's settings class; see Configuration.

Series library

Each series has its own folder in files/library/, named by its ID. The series is split across three files:

{
  "id": "gakuen-idolmaster",
  "name": "Gakuen Idolmaster",
  "input_lang": "ja",
  "output_lang": "en",
  "notes": "Gakuen Idolmaster (学園アイドルマスター) is a free-to-play roguelike deck-building game…"
}
[
  {
    "id": "lilja-katsuragi",
    "name": "Lilja Katsuragi",
    "aliases": ["葛城リーリヤ", "リーリヤ"],
    "personality": ["Shy and quiet in new situations.", …],
    "relationships": {"…": ["…"]},
    "history": ["…"]
  },
  …
]
[
  {
    "id": "初星学園",
    "term": "初星学園",
    "translation": "Hatsuboshi Academy",
    "notes": "The idol training school where the story takes place."
  },
  …
]

The backend always reads all three and joins them into one Series object, and splits it again when saving. Every library edit rewrites all three files. The joined object is shown on the Routes and API page.

Outputs

A new file with the same name replaces the old one. Files stay until they are deleted from the Translate or Transcribe page.
