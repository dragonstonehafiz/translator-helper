Files and storage

Persistent files and temporary uploads have different owners and lifetimes.

Current implementation · 3 October 2026

Everything app-owned lives under the gitignored backend/files/ folder, and every path is defined once in backend/utils/config.py. This map comes from active source paths, not an inventory of personal output files. A folder may be created only when its writer runs.

Temporary uploads

save_upload_to_temp() uses tempfile.NamedTemporaryFile(delete=False). It does not archive uploads under files/. The workflow reads the file into memory when it starts; tasks never see the path.

Cleanup has one owner at a time. Until the orchestrator accepts the workflow, the route owns the temp files and deletes them if anything is rejected. Once it is accepted, the workflow's cleanup callback deletes them when the run ends, whether it succeeded or failed.

Series library storage

load_series() reads three JSON files and combines them into one series dictionary. save_series() separates metadata, characters and glossary back into their files. Series directories are identified by their series IDs.

The library-update chain produces suggested entries. Acceptance in the UI goes through ordinary library CRUD requests before entries become persistent library data.

A missing series raises SeriesNotFoundError (404 at the HTTP boundary) and an invalid ID raises InvalidSeriesIdError (400). Translation and review treat only a missing series as "no series context".

Source: backend/library/repository.py and backend/routes/library.py.

File listing and downloads

The frontend requests a folder through file-management endpoints. The shared path helper validates folder segments and resolves them under files/outputs/. The list response contains names, sizes and modification times; download returns file content separately.

Translate names translated and reviewed; Transcribe names transcribed. The panel does not discover arbitrary output categories automatically.

Source: backend/routes/file_management.py.
