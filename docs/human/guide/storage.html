Files and storage

Persistent files and temporary uploads have different owners and lifetimes.

Temporary uploads

save_upload_to_temp() uses tempfile.NamedTemporaryFile(delete=False). It does not archive uploads under outputs/. The returned temporary path travels through the task dictionary.

Cleanup is distributed. File translation removes its input in the final task's finally; the review runner removes both inputs in its own finally. If translation fails in an earlier stage, the final task never runs, so its cleanup does not run either.

The refactor needs a defined owner for upload cleanup. Retaining uploads in an uploads/ directory would also change their lifetime.

Series library storage

load_series() reads three JSON files and combines them into one series dictionary. save_series() separates metadata, characters and glossary back into their files. Series directories are identified by their series IDs.

The library-update chain produces suggested entries. Acceptance in the UI goes through ordinary library CRUD requests before entries become persistent library data.

Source: backend/utils/library.py and backend/routes/library.py.

File listing and downloads

The frontend requests a folder through file-management endpoints. The shared path helper validates folder segments and resolves them under outputs/. The list response contains names, sizes and modification times; download returns file content separately.

Translate names sub-files/translated and sub-files/reviewed; Transcribe names transcribe-sub-files. The panel does not discover arbitrary output categories automatically.

Source: backend/routes/file_management.py.

Proposed storage changes

outputs/uploads, outputs/downloads and outputs/logs are proposals from the refactor note. They are not the current paths.

Moving translated/reviewed outputs means updating task writers and frontend folder values together. Transcription also needs attention because its writer lives in ModelManager. Log roots are constructed by chain runners, while task code writes filenames underneath them.

The note mentions renaming context-files to context. The inspected backend Python source has no active writer referencing context-files; it should not be presented as an active output pipeline without further evidence.

Library data and provider settings also need an explicit place in any eventual storage design. They are persistent application data, with different purposes from generated downloads.
