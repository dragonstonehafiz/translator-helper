Response contract

All JSON endpoints return the same outer object. Payload fields belong under data. The file download endpoint is the only application route that returns a raw body instead.

Normal JSON response

{
  "status": "success | processing | complete | idle | error | loading",
  "message": null,
  "data": {}
}

Validation error · HTTP 422

{
  "status": "error",
  "message": "Invalid request data.",
  "data": { "details": [] }
}

Several precondition failures—such as a model not being loaded or another task already running—use HTTP 200 with status: "error". Callers must inspect both the HTTP result and the envelope status.

How a background job runs

Every background job follows this sequence, with time running downwards: translate line, translate file, review, transcribe line, transcribe file and library update. The page sections below list each job's start endpoint. Jobs that produce a file also use the file-management routes. Direct requests such as library edits are a single request and response.

Shared task and file APIs

Translate, Transcribe and Library Detail poll task results. Translate and Transcribe also list, download and delete generated files.

GET/task-results/{workflow}

One snapshot of the workflow's state. progress is [current, total] for the active task. On error, the envelope message is the error and the data keeps the failed task and its last progress. A workflow that has not run since the server started is idle. Any other ID returns HTTP 400.

Processing

{
  "status": "processing",
  "message": null,
  "data": {
    "workflow": "translate_file",
    "active_task": "TaskTranslateBatches",
    "progress": [96, 312],
    "message": "Batch 12/40 complete",
    "eta_seconds": 84.0,
    "result": null
  }
}

{
  "new_characters": [
    {
      "name": "Ren",
      "aliases": [],
      "personality": ["Quiet"],
      "relationships": {"Aoi": ["Childhood friend."]},
      "history": []
    }
  ],
  "updated_characters": [
    {"id": "aoi", "field": "history", "append": "Joined the band in episode 4."},
