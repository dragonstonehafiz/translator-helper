Orchestrator

A workflow is the whole operation a user starts, such as translating a file. It runs an ordered list of tasks, each taking one typed input and returning one typed output.

Current implementation · 4 October 2026

Running a workflow

File translation, from the route call to the saved file:

Task data

Everything passed between tasks is a TaskData dataclass. Each workflow defines its own subclasses in orchestrator/task_data/, and fields have no defaults, so a missing value fails when the object is built.

FunctionWhat it does
extend(data, Target, **extra)Builds a new Target from every field of data plus the new fields. Used when a task adds information.
dataclasses.replace(data, **changes)Returns a copy of the same type with some fields changed. Used when a task only updates information.
run_label()Returns the name used for the run's log folder, usually the uploaded filename.

When a task adds information, its output type is a subclass of its input type with the new fields, so later tasks still have everything the earlier ones had. Batch planning in file translation:

Validation

The orchestrator checks the type of the data on both sides of every task, so a task can never receive or hand on the wrong data:

if not isinstance(data, task.input_type):
    raise TypeError(f"{task.task_type} expects {task.input_type.__name__}, got {type(data).__name__}.")
task.set_data(data)
output = task.run_task(report_progress=…, write_log=…)
if not isinstance(output, task.output_type):
    raise TypeError(f"{task.task_type} must return {task.output_type.__name__}, got {type(output).__name__}.")

The workflow's finish() must also return TaskData. Any of these errors fails the workflow.

Tasks

Every task subclasses BaseTask[InputT, OutputT].

MemberWhat it does
input_type, output_typeThe TaskData classes the task accepts and returns.
set_data(data), get_data()The orchestrator supplies the input; the task reads it.
run_task(report_progress, write_log)Does the work and returns the output, or raises.
task_typeThe class name, shown as the workflow's active task.

Input TranslateLineData: text, context, input_lang, output_lang.
Output TextOutputData: text.

class TaskTranslateLine(BaseTask[TranslateLineData, TextOutputData]):
    input_type = TranslateLineData
    output_type = TextOutputData

    def run_task(self, report_progress, write_log) -> TextOutputData:
        data = self.get_data()
        model_manager = ModelManager.get_instance()
        llm = model_manager.acquire_llm()
        try:
            report_progress(0, 1, "Translating the entered text", 0.0)
            translated_text = llm.infer(
                prompt=data.text,
                system_prompt=generate_translate_sub_prompt(
                    context=data.context, input_lang=data.input_lang, target_lang=data.output_lang,
                ),
            )
        finally:
            model_manager.release_llm()
        report_progress(1, 1, "Translation complete", 0.0)
        return TextOutputData(text=translated_text)

Input TranscribeClipData: audio_path, language.
Output TextOutputData: text.

class TaskTranscribeClip(BaseTask[TranscribeClipData, TextOutputData]):
    input_type = TranscribeClipData
    output_type = TextOutputData

    def run_task(self, report_progress, write_log) -> TextOutputData:
        data = self.get_data()
        model_manager = ModelManager.get_instance()
        audio = model_manager.acquire_audio()
        try:
            report_progress(0, 1, "Transcribing the selected audio clip", 0.0)
            transcript = audio.transcribe_line(str(data.audio_path), data.language)
        finally:
            model_manager.release_audio()
        report_progress(1, 1, "Transcription complete", 0.0)
        return TextOutputData(text=transcript)

Tasks don't save files, delete uploads or record their own status. They return data or raise; the workflow's finish() saves output and the orchestrator records the result or error.

Workflows

A workflow is a start function in orchestrator/workflows/. It builds the first TaskData and the task list, then passes both to the orchestrator with a finish step that turns the last output into the result and a cleanup step for temp files.

def start_transcribe_file(audio_path: Path, original_filename: str, language: str) -> None:
    data = TranscribeFileData(audio_path=audio_path, original_filename=original_filename, language=language)
    TaskOrchestrator.get_instance().run(
        WORKFLOW, [TaskTranscribeFile()], data, finish=_finish, cleanup=remove_files(audio_path),
    )


def _finish(data: TaskData) -> FileOutputData:
    filename = transcribed_filename(data.original_filename, data.language)
    return FileOutputData(output_path=save_subtitles(data.subtitles, "transcribed", filename))

The orchestrator

TaskOrchestrator is a single shared object that runs workflows one at a time on its own background thread, so routes can answer straight away while the work continues.

FunctionWhat it does
run(workflow, tasks, data, finish, cleanup)Accepts a workflow and returns at once, or raises if another one is running.
get_running_state()Returns the running workflow's state, or None.
get_state_handler()Returns the state store read by /task-results.
shutdown()Refuses new workflows and waits for the running one to finish.

Loading a workflow: run()

def run(self, workflow, tasks, data, *, finish, cleanup):
    with self._lock:
        if self._running is not None:
            raise RuntimeError("Another task is already running.")
        self._running = workflow
        self._state.start_workflow(workflow)
        # returns now; _execute runs on the worker thread
        self._future = self._executor.submit(
            self._execute, workflow, tasks, data, finish, cleanup)

Running the tasks: _execute()

def _execute(self, workflow, tasks, data, finish, cleanup):
    try:
        current = data
        for task in tasks:
            # each output is the next task's input
            current = self._run_task(workflow, task, current, run_log)
        result = finish(current)
    except Exception as exc:
        error = exc
    finally:
        cleanup()
    if error is not None:
        self._state.fail(workflow, str(error))
    else:
        self._state.complete(workflow, result)

_run_task() is the type check shown under Validation. The data passed through each workflow:

TranslationDataBuilt by start_translate_file().
TaskPrepareTranslationBatchesReturns PlannedTranslationData via extend().
TaskSelectLibraryContextReturns PlannedTranslationData via replace().
TaskTranslateBatchesReturns TranslatedSubtitleData.
finish()Saves the file, returns FileOutputData.
ReviewDataBuilt by start_review_file().
TaskPrepareReviewBatchesReturns PlannedReviewData via extend().
TaskSelectLibraryContextReturns PlannedReviewData via replace().
TaskReviewTranslatedBatchesReturns ReviewedData via extend().
TaskRetranslateReviewedLinesReturns CorrectedSubtitleData.
finish()Saves the file, returns ReviewFileOutputData.

TaskSelectLibraryContext is shared: it is created with the data type it runs on, so in review the extra fields such as the translated subtitles pass through untouched.

Progress and logging

A task never touches the state record or the log folder directly. run_task() receives two callbacks, and the orchestrator decides where their output goes.

1. The orchestrator passes in the callbacks

# TaskOrchestrator._run_task()
self._state.start_stage(workflow, task.task_type)
...
output = task.run_task(
    # fills in the workflow name, stores the rest
    report_progress=partial(
        self._state.report_progress, workflow),
    # writes one JSON file into this run's folder
    write_log=run_log.write,
)

2. The task calls them while it runs

# TaskPrepareTranslationBatches.run_task()
report_progress(
    0, 1, f"Planning semantic translation batches for "
          f"{total_lines} subtitle lines", 0.0)
planned = plan_batches(llm, indexed_lines, ...)
write_log("01-plan-translation-batches.json", {
    "task_type": self.task_type,
    **log_header,
    "batch_count": len(planned),
    "batches": [batch.to_log() for batch in planned],
})
report_progress(
    1, 1, f"Planned {len(planned)} semantic batches", 0.0)

3. Each call updates its own output

The two callbacks are independent: one updates the state record, the other writes a file.

report_progress() updates the state record

# TaskStateHandler record (read by /task-results)
{
  "workflow": "translate_file",
  "status": "processing",
  # set by start_stage() before the task runs
  "active_task": "TaskPrepareTranslationBatches",
  # the rest come from report_progress()

  "message": "Planned 4 semantic batches",
  "eta_seconds": 0.0,
  "result": null,
  "error": null
}

The folder name comes from the run's start time and the data's run_label(). It is only created on the first write_log() call, so runs that write nothing, such as line translation, leave no folder.
