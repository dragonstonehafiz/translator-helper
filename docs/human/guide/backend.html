Backend and models

The backend is organized around HTTP routes, task execution and a shared manager for model clients.

Current implementation · 3 October 2026

Startup

The server.py lifespan starts three daemon threads: one for the LLM, one for audio, and one for search. Each calls the shared manager. Readiness can still be false while initialization runs.

Server lifespanStarts loading threads.
ModelManagerCreates a client if its slot is empty, then initializes it.
Client configurationProvider code reads saved settings.
Settings pageDisplays readiness and loading errors through utility endpoints.

Initialization failures are recorded in manager error fields. On shutdown, the server lifespan waits for the startup loads and then releases the clients.

ModelManager responsibilities

A singleton means one shared instance within the backend process. The manager keeps one LLM slot, one audio slot and one Tavily slot. By default it constructs LLMDeepSeek, AudioWhisperX and SearchTavily. Claude, ChatGPT, llama.cpp and Whisper implement the same interfaces and can be swapped in.

ResponsibilityCurrent behavior
Instance ownershipCreates the client for each slot on first load and returns it through get_llm_client(), get_audio_client() and get_search_client().
Loadingload_*_model(settings) validates and saves submitted settings, then initializes the client. It is refused while that model is loading or in use; failures are stored in the *_loading_error fields.
ReadinessA model is ready when its client exists and its state is ModelState.LOADED.
Use trackingTasks call acquire_llm() / acquire_audio() / acquire_search() before using a model and release_*() when done. GET /utils/running reports these flags.
Shutdownshutdown() refuses further loads and use, then releases every client.

The manager does not run inference or save files; tasks call the clients directly. To use a different provider, change LLM_PROVIDER, AUDIO_PROVIDER or SEARCH_PROVIDER in backend/models/manager.py.

Model interfaces

LLMInterface and AudioModelInterface expose only provider_id, config, state, configure(config), initialize(), shutdown() and the operation: infer(), or transcribe_line() and transcribe_file(). transcribe_file() returns subtitles without saving them.

Each provider declares its settings once as a ModelConfig dataclass, with one field per setting and an option type (text, number, integer, boolean or dropdown). The base class reads and writes the JSON file in backend/files/config/ and builds the Settings-page form, so adding a setting means declaring one field. Saved API keys are never sent to the browser.

Source: backend/models/config.py.

Source: backend/llm/interface.py and backend/audio/interface.py.

Model status

Each provider owns a ModelState: NOT_LOADED, LOADED or ERROR. A failed request does not change it. Loading and in use are ModelManager flags; GET /utils/running reports both for the LLM, audio model and search.

The settings load request includes a provider field, but the current load handlers use request.settings and do not select a provider from that field. See backend/routes/utils.py.

Tavily search

Tavily is a concrete search client in search/, owned by ModelManager. It does not implement the LLM or audio interface. TaskWebSearch retrieves it and calls search() directly to collect snippets for library proposals.

If no queries exist, the task skips searching. If queries exist and search is unavailable, it raises an error. Source: backend/orchestrator/library/task_web_search.py.
